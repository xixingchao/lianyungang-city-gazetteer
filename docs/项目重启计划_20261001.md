## 三、批次规划

每批按《东辛经验复用与交付整改计划》第 4 节模板执行（读进度→小范围计划→改→跑→复跑门禁→抽查→写 progress 报告→更新 PROJECT_MEMORY→汇报）。

- **批次1（2026-10-01 已完成）**：源断行重排 + 机械错字修复 + 字符规范化沉回 → `body_chapters_reflowed/`（12 文件、2.46 万段）。源文件未动；全部替换留痕于 `output/reports/progress/20261001_批次1*.md`。
- **批次2：源回填重建 `body_chapters_v2/`**。以阅读版正文为底、按卷切分章节文件，用 difflib 把 8089 个页锚从旧源回贴到 v2 段落；生成后复测 v2↔阅读版覆盖率应 ≥99%。此后 v2 为唯一真值。
- **批次3：错字专项**。对本地原件 PDF 重跑 PaddleOCR + RapidOCR 双引擎，逐页共识比对 v2 文本，分歧字进待核清单；高置信形近字对（如 淮/准、馀/余 类）按白名单批量修，其余回源页图人工/视觉核验。分卷推进，每卷一个 progress 报告。
- **批次4：格式精修**。小节标题独立化（"一、二、三、"层级）、大事记年份条目结构化、目录重建。
- **批次5：vol59 方言卷正式版**。重抽 48 页原图 → 按词典模式转录双审（IPA/同音字汇/词汇卡片）→ 修 96 条失效图链 → 正式 HTML。
- **批次6：成品重建**。由 v2 源生成全书 HTML + PDF + 表格站，`audit_delivery_quality.py` 与 `audit_full_reader.py` 复跑清零。
- **批次7：交付与发布**。交付包（含 checksum 与交付说明）→ GitHub Pages（公开与否待用户定）。

## 四、风险与原则

1. 原件与归档只读；工作只在仓库内。
2. 每批一个 git commit，说明改动范围与验收结果；push 由用户确认。
3. 不确定不改：所有低置信修改只进待核清单（JSON/MD 留痕），不静默改原文。
4. 页锚 `image_page` 语义不变；v2 的锚回贴以旧源块对齐为准，回贴失败的锚登记补挂清单，不丢弃。
5. 脚本一律 UTF-8 Python，禁止 PowerShell 批量改中文文本。
